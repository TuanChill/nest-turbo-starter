## Current implementation rules

- Production responses must never fall back to mock IDs or mock records.
- A failed create/detail request must show an error; it must not synthesize a local record.
- Template instantiation must be atomic and must remap every cloned issue relationship.
- Unsupported source references must fail before creating records, or the entire transaction must roll back.
- Every feature slice must pass local checks, CI, deployment and post-deploy browser verification.

## Additional P0 fixes in progress (2026-09-15)

- CORS is now centralized to production frontend plus localhost development origins across project, auth, user, and notification services; wildcard `enableCors()` calls were removed.
- Production deployment now rebuilds and restarts the `web` service when frontend files or the deployment script change; the prior backend-only deployment path could leave `pm.capylabs.io` on an older frontend build.
- Document and review responses no longer substitute the seeded `ln` member when an author/creator is missing. Documents restrict creator enrichment to the visible team/workspace. Reviews now carry workspace scope through `Migration20260916100000` and enforce it on list/read/update.
- Issue creation now rejects unknown status/priority IDs, requires assignees to be members of both the issue team and its workspace, and validates cycle and parent-issue team membership before persistence.
- The public seed endpoint now returns not-found in production. My Issues counts and lists use only authenticated-user/server issue data; they no longer fall back to the first mock user or local mock records. Template queries also wait for a verified workspace ID during legacy-route redirects.
- Deployment locking now waits for an active deploy to finish for up to ten minutes so a queued release does not fail immediately on a held remote lock.
- Deployment now reclaims all unused Docker objects before `git fetch` and image builds, because the 36 GB production host had reached 100% usage; the cleanup intentionally preserves named volumes and stateful PostgreSQL/Redis data. Corepack is also relocated to a shared image path instead of the deploy user's home cache.
- Member responses now filter returned team IDs to teams visible to the requester, preventing cross-workspace team metadata from leaking through an otherwise valid member lookup. Project reads now reject legacy/corrupt multi-workspace team links instead of returning a project through a secondary team with foreign workspace metadata. The production Agent route now returns an explicit not-configured error instead of canned workspace data; the UI surfaces that API error.
- Agent example prompts now come from the backend endpoint, and production rejects both examples and chat when the integration is not configured; the web page no longer renders a mock skills/canned-response experience.
- Saved-view create/update now validates referenced projects against the view workspace and selected team, preventing cross-workspace or unrelated-team project references.
- Review detail, diff, and guide views now consume persisted API payloads only; synthetic review/diff fallbacks were removed. Review issue references are validated against the same accessible workspace/team, and review timestamps are returned as real relative times.
- Issue creation no longer falls back to the arbitrary `ENG`/`CORE` team IDs. It now requires an actual route/project-selected team and shows an error before sending an invalid request.
- Backend issue and document-folder creation now reject missing team context instead of selecting the first accessible team or legacy `ENG`/`CORE` IDs; the document dialog scopes folder queries to the current team.
- Team/project/issue headers no longer fabricate a `CORE` team while live data is loading or missing. Team lists use persisted cycle and created/updated timestamps, and onboarding rejects an unusable team key instead of silently substituting `ENG`.
- Initiative reads now discard persisted project links whose primary team is missing or belongs to another workspace, and initiative creation requires explicit workspace context instead of choosing the first accessible workspace.
- Issue-template references now require target-workspace members and labels, and enforce mutually exclusive label groups before a template is persisted or updated.
- Issue templates now expose and apply persisted project, cycle, due-date, full status/priority catalogs, labels, and rich descriptions; stale or cross-team project/cycle references are rejected by the backend instead of falling back to current issue context.
- Issue detail reads now discard stale or cross-team relation rows and cross-team sub-issue links instead of exposing persisted identifiers outside the current team.
- Member profiles now use persisted member and label data without `CORE`, generated join dates, generated avatars, or mock label breakdowns. Comment submission no longer inserts a fabricated optimistic activity; API success supplies the persisted activity and API failure remains visible.
- Google OAuth now requires the configured client ID and a verified Google profile; missing configuration or profile data produces an explicit error instead of mock credentials/profile values.
- Notification preference settings no longer expose hard-coded channel statuses or inert switches; until persisted preferences exist, the route shows an explicit unavailable state while the authenticated inbox read/unread/delete contract remains available.
- Review and saved-view creation no longer silently chooses the first workspace for members who belong to multiple workspaces; an explicit workspace is required in that case. Legacy database defaults that could create `CORE`, `ln`, or `circle-workspace` foreign identities were removed and migrated; document-folder creation now requires a real team ID.
- Project-template instantiation now has dedicated regression coverage for parent-key remapping, issue-relation remapping, invalid relation references, and transaction failure visibility; invalid cloned issue or relation creation propagates the error instead of returning a partial project. The authenticated simulation also verifies a cloned relation against the persisted detail API.
- Cycle progress now records one persisted snapshot per cycle/day, merges legacy persisted burn-up points, and exposes historical snapshots through the authenticated cycle history endpoint; completed-cycle graphs no longer depend on a mutable JSON-only counter.
- Cycle creation now allocates team-local numbers from server state and globally collision-safe IDs, so a stale client number or another team’s legacy numeric cycle ID cannot fail creation or leak across teams.
- Issue filter label options now come from the authenticated workspace label API; the previous bundled mock label catalog was removed from that production path.
- Issue and project mutation paths now reject unknown status/priority/health values, mismatched status categories, invalid project progress, invalid dates, and reversed project date ranges before persistence; focused property-rule tests cover the contract.
- Saved-view detail now applies persisted team/project scope and advanced filters to live API results, restores persisted issue display settings, and no longer exposes an inert issue-detail subscription or attachment/reaction action.
- The editor disables StarterKit's built-in link/underline extensions when registering the configured versions, removing the duplicate-extension warning observed in the authenticated production issue-detail smoke.
- Issue reactions now have an authenticated removal endpoint; the activity UI uses persisted `userIds` to toggle the current member's reaction and rolls back with an error toast if the mutation fails.
- File uploads now have a persisted, target-scoped presign/complete/list contract plus authenticated signed downloads with an explicit unavailable response when storage is not configured; completion never succeeds without a storage existence check. Issue detail and project activity consume that contract through real browser upload flows and only display completed attachments; storage credentials and a browser upload E2E remain unverified.
- Workspace navigation no longer invents a `circle-workspace` route when the authenticated workspace parameter is absent; the affected sidebar surfaces render no workspace links until a real route context exists.
- Label list and group queries now accept and enforce the active workspace, preventing a member’s other accessible workspaces from appearing in the current workspace’s label pickers.
- Label hooks now wait for the authenticated workspace list to resolve the route slug, preventing legacy or foreign route labels from being queried during hydration.
- Team creation now requires an explicit accessible workspace and rejects unscoped teams; corrupt teams without a workspace are excluded from template team filters rather than being matched through an arbitrary workspace. Workspace access now also includes validated ownership, filters direct team membership through real workspace rows, and no longer fabricates a default workspace when none exists.
- Project- and issue-template team checks now reject teams with a missing workspace association as well as teams from another workspace; a malformed legacy team cannot bypass template isolation through a create, update, or instantiate path.
- Issue, project, initiative, view, team, and member list hooks now resolve the active route slug to a real workspace ID before querying; backend list/detail paths enforce the same workspace boundary. Corrupt cycle/project issue rows are filtered by their owning team, and a project’s primary team is retained when secondary team links are present.
- The new-issue dialog initializes only on a closed-to-open transition, so background query refetches cannot erase typed title/description text or steal focus. The frontend workflow catalog no longer offers the `testing` or `blocked` IDs rejected by the issue API; team settings use the live label count and do not report unsupported retirement as successful.
- Initiative project links now reject and suppress projects whose secondary team links belong to another workspace. Project creation no longer invents a start date when the caller leaves it unset; the persisted date remains optional.
- Unsupported settings sections are removed from production navigation and their direct routes show an explicit unavailable state without inert create/filter controls or synthetic empty records.
- `test-all-apis.sh` now delegates to `scripts/circle-user-simulation.sh`, an authenticated simulation harness that creates and verifies workspace/team, project, templates, labels/groups, initiative, cycle, issues, hierarchy, relation, comment, reaction, property updates, and template cloning. It requires an explicit bearer token and workspace/team context (or an explicit `CREATE_WORKSPACE=1` opt-in); it no longer uses unauthenticated calls or fallback IDs.
- Live issue/project display metadata no longer comes from `mock-data`: canonical workflow status, priority, project-health, member-presence, and cycle formatting modules now live under `apps/web/lib`; legacy fixture modules retain only fixture data and type compatibility.
- Project activity health labels/colors now also come from the canonical `apps/web/lib/project-health` catalog; the live activity route no longer imports runtime metadata from `mock-data`.
- Google authentication no longer accepts unverified profiles or mismatched audiences: ID tokens require a verified profile, access-token flows validate Google token audience and `verified_email`, userinfo must match the token email, and database-sync failures abort login instead of issuing a token for a fallback user. Password sign-up no longer generates a synthetic avatar, and Google member IDs use deterministic collision-safe allocation.
- Inbox rendering accepts a persisted notification with no visible actor and renders an explicit unknown-member state instead of dereferencing `null`. Read/unread mutations now roll back the optimistic state and expose the API error when persistence fails.
- SES invite delivery no longer logs a simulated email or returns success without credentials; missing SES configuration is an explicit unavailable delivery result covered by a service regression test.
- The integrations settings route no longer renders a hard-coded provider catalog or fake enabled cards; it shows an explicit unavailable state until provider connection and permission APIs exist.
- Connected accounts and code-review settings no longer claim providers are connected or render an invented diff; both now show an explicit unavailable state until their persisted provider/repository contracts exist.
- Issue subscriptions are now persisted in `issue_subscriptions`, automatically added for issue creators, assignees and mentioned commenters, included in notification recipient resolution, and exposed through authenticated issue subscription endpoints. The My Issues “Subscribed” tab and issue context menu consume the persisted state instead of treating creator/assignee records as subscriptions.
- Project subscriptions are now persisted in `project_subscriptions`, scoped through the project’s accessible teams, and exposed through authenticated GET/POST/DELETE endpoints. The project health popover now renders the authenticated subscription state and links “New update” to the real project activity route.
- Project membership controls now use the existing authenticated `GET/PUT /projects/:id/members` contract; the picker only offers workspace-visible members and backend tests cover cross-workspace rejection before mutation. Decorative Slack, favorite, “learn more,” and activity controls were removed or changed to real navigation/explicit unavailable states.
- The AI & Agents settings surface no longer renders fake enabled integrations, local-only switches, or empty click handlers; it now uses the same explicit unavailable state as other unconfigured integrations. Initiative activity “See all” now navigates to the persisted activity tab.
- Project resources can now be added and removed through the persisted project update API; team resource shortcuts open the live document creation/list surfaces, and unsupported project-status/member-filter actions are disabled with an explicit explanation instead of silently doing nothing.
- Project member controls no longer fall back to a project payload when the persisted member endpoint fails; the picker reports an unavailable state, and the workspace member directory renders a retryable API error instead of an empty list. Member names, emails, teams, and join dates now render directly from the real member API without fixture-style name splitting, hash-based presentation, or a hard-coded year.
- The members header no longer exposes an inert display control or reports a fabricated zero count when the member request fails; it now removes the unsupported control and marks the count unavailable.
- Production web builds now receive the exact deploy revision as a build input, preventing the persisted Next incremental cache from serving stale frontend bundles after a successful image rebuild.
- Primary Teams, Cycles, Initiatives, and Issues list surfaces now expose retryable API error states instead of rendering empty arrays when their live queries fail.
- Cycle issue and project issue surfaces now expose retryable errors for their issue, cycle/project-detail, view, and project queries instead of silently treating failed requests as empty data; activity feeds use an explicit unknown-member label when actor data is unavailable.
- Issue detail now distinguishes a failed issue/activity request from a genuine not-found response and exposes retryable API error states for both.
- Issue list, search, cycle, project, My Issues, member-profile, and saved-view creation surfaces no longer merge local Zustand records into live results; filter controls receive the caller's scoped API response for option discovery.
- Issue creation for a project no longer selects the first accessible project team when `teamId` is omitted: the backend uses the accessible primary team or requires an explicit team for ambiguous multi-team projects. Project creation also preserves an unset start date instead of fabricating today.
- Personal Preferences no longer exposes local-only switches for behavior that the server does not persist; the default workspace, sidebar customization, and theme controls remain functional, while unsupported home/editor/desktop/automation settings are explicitly unavailable.
- `scripts/circle-user-simulation.sh` now exercises authenticated project subscriptions, project updates/milestones, cycle progress/history, comment mentions/reactions, and backend rejection of conflicting mutually-exclusive labels in addition to the existing template/issue/relationship flow.
- The authenticated simulation harness now asserts the live detail response fields (`activity`, `subIssueIds`, and relation `identifier`) and covers the persisted issue subscription lifecycle (read, unsubscribe, resubscribe); `bash -n scripts/circle-user-simulation.sh` passes. It still requires an explicit bearer token and workspace/team context for execution.
